## How I color-code notes

Color helps me spot commands and important details quickly. It also makes it easy to skim past something, so the explanation beside each command still matters.

| Color | What it means |
| :--- | :--- |
| 🟫 **Brown** | Syntax, commands, flags, and parameters |
| 🟦 **Blue** | Titles for a specific lesson or procedure |
| 🟪 **Purple** | Important version details, constraints, and things to reconsider |
| 🟩 **Green** | Verified vulnerability or observed result |
| ⬜ **White** | General explanation and context |

The color may look different when exported to PDF. Brown, in particular, can appear yellow.

The goal is to make the testing path reproducible: what I saw, why I chose a test, what it returned, and what would change the conclusion. A hypothesis stays a hypothesis until I verify it.

HTB's [publication guidelines](https://help.hackthebox.com/en/articles/5188925-streaming-writeups-walkthrough-guidelines) prohibit revealing solutions for active machines.
